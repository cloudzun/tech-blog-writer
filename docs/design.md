# 技术博客写作助手 - 设计文档

## 设计目标

创建一个**完整、易学、实用**的教学用 Skill，展示 OpenClaw Skills 开发的最佳实践。

---

## 核心设计原则

### 1. 完整性（Completeness）

**目标**：包含所有标准 Skill 组件

**实现**：
- ✅ SKILL.md（核心定义）
- ✅ scripts/（Python 脚本）
- ✅ templates/（模板文件）
- ✅ config/（配置文件）
- ✅ docs/（文档）
- ✅ data/（数据文件）

---

### 2. 易学性（Learnability）

**目标**：降低学习门槛，快速上手

**实现**：
- 清晰的注释和文档
- 简单的脚本逻辑
- 标准的代码结构
- 丰富的示例

---

### 3. 实用性（Practicality）

**目标**：真实可用，不是玩具

**实现**：
- 真实的质量检测逻辑
- 可运行的脚本
- 实用的模板
- 合理的评分标准

## 架构设计

### 1. 分层架构

```
用户交互层
    │
    ▼
SKILL.md（指令层）
    │
    ├──► scripts/（执行层）
    │    ├── quality_checker.py
    │    └── title_generator.py
    │
    ├──► templates/（模板层）
    │    └── tutorial-template.md
    │
    ├──► config/（配置层）
    │    └── settings.json
    │
    └──► data/（数据层）
         └── examples.json
```

---

### 2. 数据流

```
用户输入
    │
    ▼
需求分析（SKILL.md）
    │
    ▼
内容创作（SKILL.md + templates/）
    │
    ▼
质量检测（scripts/quality_checker.py）
    │
    ├──► 通过（≥70分）
    │    └──► 输出最终文章
    │
    └──► 不通过（<70分）
         └──► 返回修改建议 → 重新创作
```

## 模块设计

### 1. SKILL.md

**职责**：
- 定义 Skill 元信息（YAML Frontmatter）
- 提供详细指令（Markdown Body）
- 组织工作流程
- 定义规则约束

**设计要点**：
- 使用清晰的章节结构
- 提供好/坏示例对比
- 说明工具调用方式
- 记录版本历史

---

### 2. quality_checker.py

**职责**：
- 检测文章质量
- 生成评分报告
- 提供改进建议

**设计要点**：
- 4个维度独立检测
- 每个维度有明确的评分标准
- 支持 JSON 输出（便于解析）
- 提供可读的文本报告

**评分逻辑**：

| 维度 | 检测项 | 分值 |
|------|--------|------|
| 技术准确性 | 代码示例 | 10 |
| | 语言指定 | 5 |
| | 版本号 | 5 |
| | 输出示例 | 10 |
| 可读性 | 段落长度 | 10 |
| | 标题分层 | 10 |
| | 列表使用 | 5 |
| 实用性 | 步骤说明 | 10 |
| | 完整示例 | 10 |
| | 常见问题 | 5 |
| 结构完整性 | 标题 | 5 |
| | 摘要 | 5 |
| | 总结 | 5 |
| | 逻辑连贯 | 5 |

---

### 3. title_generator.py

**职责**：
- 生成标题候选
- 应用标题公式
- 评估标题质量

**设计要点**：
- 3种标题公式（教程/原理/实战）
- 每种公式多个模板
- 评分算法（长度、数字、动作词等）
- 排序输出

**标题公式**：

1. **教程型**：[时间] + [动作] + [技术] + [结果]
   - 示例：5分钟搞懂 Docker 容器化

2. **原理型**：深入理解 [技术] 的 [核心概念]
   - 示例：深入理解 React Hooks 的工作原理

3. **实战型**：[动作] + [技术] + [场景]
   - 示例：用 Docker 实现微服务部署

---

### 4. templates/

**职责**：
- 提供标准化的文章结构
- 降低创作门槛
- 确保质量一致

**设计要点**：
- 使用占位符（{variable}）
- 清晰的章节划分
- 包含所有必需部分

---

### 5. config/

**职责**：
- 存储可变参数
- 支持个性化配置
- 便于维护和更新

**设计要点**：
- JSON 格式（易读易写）
- 分类组织（preferences、thresholds、formulas 等）
- 提供默认值

---

## 工作流设计

### 完整流程

```
步骤1：需求分析
    输入：用户的写作主题
    处理：确定目标读者、技术点、文章类型
    输出：文章大纲

步骤2：内容创作
    输入：文章大纲
    处理：应用模板、填充内容、添加示例
    输出：文章草稿

步骤3：质量检测
    输入：文章草稿
    处理：调用 quality_checker.py
    输出：质量评分报告

步骤4：优化改进
    输入：质量评分报告
    处理：根据建议修改
    输出：最终文章
```

## 常见问题

### Q1：为什么不用独立的 prompts/ 文件夹？

**A**：OpenClaw 2.10+ 版本改为使用 SKILL.md 单文件结构，支持 Hot Reloading，更易维护。

### Q2：为什么用 Python 而不是 JavaScript？

**A**：Python 生态丰富、语法简洁、跨平台支持好，更适合数据处理和文本分析。

### Q3：如何扩展新功能？

**A**：
1. 在 SKILL.md 中添加新的指令章节
2. 在 scripts/ 中添加新的脚本
3. 在 config/ 中添加新的配置
4. 在 templates/ 中添加新的模板
